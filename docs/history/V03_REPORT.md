## 변경된 동작

### 실시간 파라미터

- 슬라이더는 `input` 이벤트에서 숫자 표시를 즉시 동기화합니다. 숫자·Seed·배경 종류 변경도 감지합니다.
- 마지막 입력 후 150ms debounce로 한 번 재생성합니다. 미완성 빈 숫자는 적용하지 않고 입력 대기 상태를 표시합니다. 최종 값을 원래 값으로 되돌리면 불필요한 재생성을 취소합니다.
- Overview/Drive가 동일한 재생성 함수를 사용합니다. 동일한 Params/Seed로 생성한 하나의 Track을 도로·연석·보도·배경·장애물·미니맵·충돌 계산에 전달합니다.
- Generate track, 초기화, Seed 버튼, R 단축키는 유지합니다. 수동 생성은 예약된 자동 생성을 취소해 뒤늦게 중복 적용되지 않게 합니다.
- 기존 환경 그룹의 geometry/material/instance 자원 해제 경로를 유지합니다. 미니맵은 기존 캔버스 캐시를 다시 그립니다.
- 재생성마다 차량 전체 반경이 들어가는 시작 위치를 검증하고 속도·실제 속도 벡터·입력 키·시간 누적량을 초기화합니다. Drive 모드는 유지하며 새 위치로 카메라와 미니맵을 즉시 동기화합니다. 대기·갱신·완료와 안전 재배치/속도 0을 상태 표시줄로 알립니다.

### 아스팔트 경계 충돌

- 보도 바깥 경계를 주행 경계로 쓰던 계산을 제거했습니다. 연석·보도는 배경이며 차량은 아스팔트 안에서만 움직입니다.
- Track의 `roadEdges`는 도로 메시의 실제 float32 정점입니다. 3D 아스팔트 외곽·미니맵·충돌이 같은 좌표를 공유합니다. 원본 중심선/PRNG/직선과 곡선 생성 방식은 유지합니다.
- 차량 반경은 7.2u입니다. 최대 약 7.17u인 차체 모서리를 감싸므로 고저차에서 피치가 생겨도 차체·바퀴·전조등의 수평 외곽을 보수적으로 포함합니다.
- 중심선 투영은 이전 구간 주변을 검사하고 폐곡선 끝을 순환합니다. 가까운 별도 구간으로 순간 이동하지 않는지 독립적인 평행 구간 테스트로 검증합니다. 실제 제한은 중심선 거리만으로 정하지 않고 양쪽 메시 경계까지의 부호 있는 거리를 사용합니다. 따라서 급커브의 국소 폭과 모서리도 반영됩니다.
- 충돌 위치는 반경과 0.002u 여유를 확보하도록 안쪽으로 보정합니다. 실제 월드 속도 벡터의 바깥 방향 성분만 제거하고 접선 성분을 유지합니다.
- 최대 1/120초 단위로 이동을 나눕니다. 최고 속도 160u/s에서도 한 단계 이동은 약 1.34u입니다. 장애물 보정 후에도 도로 경계를 다시 적용합니다.
- 차량 높이는 아스팔트와 동일한 삼각형의 무게중심 좌표로 계산합니다. 겹친 메시에서는 위쪽 표면을 선택합니다. 카메라와 미니맵은 보정된 실제 차량 위치를 사용합니다.

### 자원 및 메모리

- 기존 혼합 형상 **100회 재생성**: 같은 최종 형상에서 geometry 33, texture 0, shader program 4, object 45, draw call 60으로 동일했습니다. GC 후 JS heap은 8,826,076 → 9,276,108 bytes, backing storage는 동일했습니다. 폐기 후 geometry/texture는 모두 0개였습니다.
- 새 입력 경로 **100회 자동 갱신**: geometry 33, texture 0, draw call 60, triangle 12,372로 동일했습니다. GC 후 JS heap은 10,641,224 → 11,123,536 bytes, backing storage는 6,936,765 bytes로 동일했습니다.
- 두 검사 모두 별도 10회 워밍업과 동일 형상 비교를 수행합니다. heap 증가는 허용 범위 4MiB, backing storage 증가는 2MiB 이내를 검사합니다. 100회 유한 시험으로 장시간 누수가 절대 없다고 단정하지는 않습니다.
